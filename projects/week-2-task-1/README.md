# Неделя 2, задание 1: первый агент

Генератор музыкальных питчей из первой недели теперь работает как отдельный агент с сайтом и CLI. `PitchAgent` самостоятельно формирует HTTP-запрос к DeepSeek API, получает ответ, хранит историю диалога и считает использованные токены.

## Чем агент отличается от одиночного API-вызова

- конфигурация модели хранится в `AgentConfig`;
- системный промпт и работа с API скрыты внутри `PitchAgent`;
- каждый успешный запрос и ответ добавляются в стек `messages`;
- следующий запрос отправляется вместе с историей, поэтому агент понимает уточнения;
- интерфейс получает от агента только готовый текст.

## Требования

- Python 3.11+
- API-ключ DeepSeek

Сторонние библиотеки не требуются. Создайте `.env` в корне репозитория:

```env
DEEPSEEK_API_KEY=your_api_key
```

## Запуск сайта

Из корня репозитория:

```powershell
python projects/week-2-task-1/web.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Из папки проекта достаточно `python web.py`. Другой порт: `python web.py --port 8001`.

1. Заполните артиста, название и описание трека. Нажмите «Написать питч».
2. Продолжайте разговор в поле «Твоё сообщение». Отправка — кнопкой или `Ctrl + Enter` (`Cmd + Enter` на macOS); обычный Enter переносит строку.
3. Копируйте нужные ответы кнопкой «Скопировать». «Новый диалог» с подтверждением очищает переписку и статистику.

Интерфейс на русском; агент по умолчанию пишет питчи на английском. Данные трека закрепляются за диалогом, уточнения отправляются с полной историей. Статистика показывает реальные сообщения и токены из API. Во время ожидания повторная отправка и сброс заблокированы. При ошибке черновик остаётся; после потери связи сначала проверяется состояние диалога, чтобы не отправить запрос повторно вслепую.

Сайт слушает только `127.0.0.1`: предназначен для локального просмотра и демонстрации куратору. Ключ остаётся в Python-процессе и не передаётся браузеру. Каждый браузер получает отдельную сессию через HttpOnly-cookie; вкладки одного браузерного профиля разделяют её. Используйте одну вкладку для отправки сообщений.

Для временного доступа с телефона запустите Cloudflare Quick Tunnel, скопируйте выданный HTTPS-адрес и перезапустите сайт с точным адресом:

```powershell
cloudflared tunnel --url http://127.0.0.1:8000
python web.py --public-origin https://random-name.trycloudflare.com
```

Адрес публичный: не публикуйте ссылку и остановите туннель через `Ctrl + C` сразу после показа. Сервер принимает только указанный адрес, остаётся привязан к `127.0.0.1` и ставит `Secure` для публичной cookie.

История хранится в памяти сервера, сохраняется при обновлении страницы и исчезает после перезапуска сервера или двух часов бездействия. Данные сообщения отправляются облачному DeepSeek API. Новых библиотек, CDN-шрифтов и сборщика нет; интерфейс использует HTML, CSS и JavaScript. Для остановки сервера — `Ctrl + C` в терминале.

## Запуск CLI

Из корня репозитория:

```powershell
python projects/week-2-task-1/main.py
```

Пример первого запроса:

```text
Name: Astin Ray, VAVA - TAKIPARIO
Description: agressive phonk with female vocal
```

После первого ответа можно проверить память агента:

```text
Revision request (or exit): Make it shorter and more energetic.
```

Агент отправит уточнение вместе с предыдущими сообщениями. В конце сессии программа покажет количество сохранённых сообщений и суммарное число API-токенов.

## Параметры агента

Параметры задаются в `AgentConfig`:

```python
model: str = "deepseek-v4-flash"
temperature: float = 0.5
top_p: float = 1.0
max_tokens: int = 250
timeout: int = 60
```

## Проверка

```powershell
python -m unittest discover projects/week-2-task-1
```

Тесты проверяют историю, статистику токенов, восстановление после ошибки, серверные сессии и проверку HTTP-запросов. Тестовые ответы подменяются локально: проверки не расходуют API-токены.
