# День 10: стратегии контекста — GOOST CHAT

Три стратегии памяти в локальном чате. Основа — GOOST CHAT с историей в SQLite и подсчётом токенов. Полная переписка сохраняется независимо от выбранного контекста модели.

## Запуск

Из корня репозитория:

```powershell
python projects/week-2-task-5/web.py --port 8767
```

Открыть http://127.0.0.1:8767/. Ключ `DEEPSEEK_API_KEY` берётся из окружения либо корневого `.env`. Нужны Python 3.10+ и доступ к DeepSeek API; дополнительных Python-зависимостей нет. База: `projects/week-2-task-5/data/context.sqlite3`, каталог исключён из Git.

## Стратегии

| Стратегия | Контекст модели |
| --- | --- |
| Скользящее окно (`sliding_window`) | Системная инструкция, последние N завершённых пар и новое сообщение |
| Закреплённые факты (`sticky_facts`) | Системная инструкция, объект фактов, последние N пар и новое сообщение |
| Ветвление (`branching`) | Полная история выбранной ветки, включая общий префикс до разделения |

Окно: 1–20 ходов, по умолчанию 3. Стратегия и окно меняются только в пустом чате. Название можно менять позже. Сообщения, выпавшие из окна, остаются видны в полной переписке.

Факты требуют двух API-вызовов на ход: извлечение памяти, затем ответ. Извлекатель получает **только предыдущие факты и текущее сообщение пользователя**. Утверждения ассистента не становятся источником памяти. Строгий JSON: до 12 пар строк, ключ до 60 символов, значение до 240 символов, объект до 4096 байт UTF-8. Повторяющиеся ключи, вложенные значения и обрезанный ответ отклоняются. Исправления пользователя должны обновлять прежнее значение; смысловую корректность определяет модель.

Факты передаются как пользовательские данные, а не системные инструкции. Предпросмотр использует уже сохранённую память и не вызывает API. Итоговый лимит проверяется после извлечения. При переполнении ответ не запрашивается; история и факты не меняются. Уже выполненное извлечение может тарифицироваться.

## Ветви A/B

После завершённого хода можно создать две независимые ветви. Обе получают копию префикса до выбранного хода включительно. Последующие сообщения исходного чата и соседней ветви в контекст не попадают. Сохраняются `parent_id`, `checkpoint_turn` и метка A/B. Факты исходного чата не копируются: полный текст префикса позволяет не переносить сведения из будущих ходов.

Обе ветви и снимок результата создаются одной SQLite-транзакцией. Повтор с тем же `request_id` возвращает прежний результат; другой checkpoint с тем же ID получает 409. Ветки принадлежат владельцу браузерной cookie, чужой владелец получает 404. Удаление исходного чата не удаляет независимые ветви.

## Сценарий демонстрации

1. Скользящее окно N=1. Сообщить: «Мой проект называется Север, бюджет 80 тысяч». Сделать ещё несколько ходов и спросить название и бюджет. Раннее сообщение выпадет из контекста.
2. Закреплённые факты N=1. Повторить вводные, проверить панель памяти, уточнить: «Теперь бюджет 95 тысяч». Снова спросить после нескольких ходов. Проверить обновление и сохранение факта за пределами окна.
3. Ветвление. Сообщить: «Планируем запуск музыкального релиза». Создать A/B после ответа. В A продолжить «Бюджет 10 тысяч, только органический рост», в B — «Бюджет 100 тысяч, добавим рекламу». Сравнить независимые продолжения и исходную историю.

Качество реальных ответов зависит от модели. Автотесты используют подставной API и не заменяют живое сравнение.

## Выводы живого запуска

Каждая стратегия была проверена в отдельном чате на 12 пользовательских запросах с одинаковым набором фактов о проекте StageFlow. При скользящем окне из 3 ходов ранние вводные перестали попадать в запрос модели: итоговый ответ сохранил недавние ограничения, но потерял часть первоначального контекста. Это самый простой и предсказуемый по размеру способ, однако важные факты нужно повторять вручную.

Режим закреплённых фактов в этом запуске не дал ожидаемой памяти: извлекатель оставил объект фактов пустым, поэтому итоговый ответ также потерял раннее название проекта. Это полезный отрицательный результат — качество стратегии зависит не только от размера окна, но и от надёжности отдельного структурированного извлечения. Для production-сценария нужны строгая схема нужных полей, проверка полноты и повтор извлечения при некорректном результате.

Ветвление показало наиболее наглядный и точный результат. После 8-го хода были созданы две независимые ветви: A получила Брест, бюджет 120 000 рублей и жёлтый цвет; B — Минск, 60 000 рублей и синий цвет. Обе сохранили общий префикс, не смешали последующие данные, а исходный чат остался без изменений. Цена этого подхода — рост контекста вместе с длиной каждой ветви; при длинных диалогах ветвление стоит сочетать со сжатием или ограничением истории.

Итог: скользящее окно подходит для кратких локальных задач, закреплённые факты — для заранее определённой памяти при надёжном извлечении, ветви — для альтернативных сценариев, которые должны развиваться независимо.

## Токены и стоимость

Предварительная оценка — эвристика по UTF-8. Лимит контекста 16 384 токена и резерв ответа 2 048 задаются в `AgentConfig`. Полная история ветки тоже может упереться в лимит: HTTP 422.

`turn_metrics` хранит оценку контекста, `provider_usage` ответа и `cost`. Для фактов отдельно записываются `facts_usage` и `facts_cost`; общий `total_tokens` учитывает оба успешных вызова. Отсутствующее usage остаётся неизвестным. Стоимость — диапазон из таблицы проекта для `deepseek-v4-flash` от 2026-09-09, а не актуальный счёт провайдера. Без необходимой детализации API или для другой модели стоимость неизвестна. Неуспешные вызовы не входят в метрики успешных ходов, но могут попасть в счёт API.

## API

- `GET /api/chats` — свои чаты.
- `POST /api/chats` с `{ "strategy": "sticky_facts", "window_turns": 3 }` — новый чат; оба поля необязательны.
- `GET /api/chats/:id` — полный чат, память, метрики и оценка.
- `PATCH /api/chats/:id` с `{ "strategy": "sliding_window", "window_turns": 2 }` — настройки пустого чата; отдельно `{ "title": "Название" }` меняет название.
- `POST /api/chats/:id/token-preview` с `{ "message": "Привет" }` — оценка без API.
- `POST /api/chats/:id/messages` с `{ "message": "Привет", "request_id": "unique-id-123" }` — ответ с защитой от повторного выполнения.
- `POST /api/chats/:id/branches` с `{ "checkpoint_turn": 1, "request_id": "branch-id-123" }` — `{ "branches": [chatA, chatB] }`, 201 при создании, 200 при повторе.
- `DELETE /api/chats/:id` — удалить чат.

DTO дополнен `strategy`, `window_turns`, `facts` (объект строк), `parent_id`, `checkpoint_turn`, `branch_label`. Предпросмотр: `selected_turns`, `total_turns`, `facts_count`, `strategy`. Ошибки: 400 — ввод, 404 — отсутствующий/чужой чат, 409 — занятость или конфликт, 422 — контекст, 502 — модель. Повтор завершённого запроса возвращает снимок; запрос с неизвестным исходом не отправляется провайдеру повторно автоматически.

```powershell
cd projects/week-2-task-5

```

Проверяются выбор контекста без изменения истории, JSON фактов и источник памяти, usage, ошибки модели, переполнение, миграция SQLite, атомарность сохранения/ветвления, изоляция владельцев и повторы HTTP. Сервер работает одним процессом с блокировкой изменений на владельца; нескольким процессам потребуется координация через БД.
