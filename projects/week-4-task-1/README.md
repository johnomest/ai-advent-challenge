# День 16 — подключение к Airtable MCP

Минимальный Python-клиент подключается к официальному Airtable MCP по Streamable HTTP, устанавливает MCP-сессию, запрашивает `list_tools()` и выводит доступные инструменты в консоль. Инструменты не вызываются и данные Airtable не изменяются.

## Что изучаем

- подключение MCP SDK к удалённому серверу;
- авторизацию Bearer-токеном;
- согласование версии протокола;
- получение схем инструментов через `list_tools()`.

## Установка и запуск

Из корня репозитория:

```powershell
python -m pip install -r projects/week-4-task-1/requirements.txt
python projects/week-4-task-1/main.py
```

Клиент читает `AIRTABLE_PAT` из переменной окружения или корневого `.env`:

```dotenv
AIRTABLE_PAT=pat...
```

Токен нельзя добавлять в код, README, видео или Git. Для этого задания достаточно read-only scopes:

```text
data.records:read
schema.bases:read
data.recordComments:read
workspacesAndBases:read
```

Доступ токена также должен быть ограничен только нужными базами. Сам файл `.env` исключён из Git.

## Ожидаемый результат

```text
Connected: https://mcp.airtable.com/mcp
Protocol: ...
Tools: ...

01. list_bases
    ...
```

Фактические названия и количество инструментов определяет Airtable. Код не хранит их заранее.

## Проверка

```powershell
Push-Location projects/week-4-task-1
python -m unittest -v
Pop-Location
```

Юнит-тесты проверяют безопасную загрузку конфигурации. Основная проверка задания — живой запуск клиента: должны появиться URL сервера, версия протокола и непустой список инструментов.

## Сценарий видео

1. Показать `main.py`: URL Airtable, Bearer-заголовок без значения токена и вызов `list_tools()`.
2. Запустить `python projects/week-4-task-1/main.py`.
3. Показать строку `Connected`, согласованную версию протокола и количество инструментов.
4. Прокрутить несколько имён и описаний инструментов.
5. Подвести итог: клиент установил MCP-соединение и получил инструменты; ни один инструмент не был вызван.

Не открывать `.env` во время записи.

## Вывод

Airtable MCP скрывает детали REST API за стандартным контрактом MCP. Клиенту достаточно знать адрес сервера и способ авторизации: список инструментов и их схемы сервер сообщает сам. Это упрощает подключение сервиса к разным агентам, но передача всей схемы инструментов расходует контекст, поэтому подключать следует только действительно нужные MCP-серверы.
