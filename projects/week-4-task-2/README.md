# День 17 — первый собственный MCP-инструмент

Локальный MCP-сервер оборачивает публичный MusicBrainz API в инструмент `search_recordings`. Консольный агент на DeepSeek получает схему инструмента через MCP, самостоятельно вызывает его, получает реальные данные каталога и использует их в финальном ответе.

## Цель задания

Сделать полный цикл работы инструмента:

1. зарегистрировать MCP tool;
2. явно описать его входные параметры;
3. вернуть структурированный результат;
4. подключить MCP-сервер к агенту;
5. дать модели автоматически вызвать инструмент и обработать ответ.

## Что изучаем

- устройство MCP-сервера и регистрацию tool;
- генерацию JSON Schema из Python-аннотаций;
- локальный транспорт `stdio`;
- преобразование MCP-схемы в формат tools для LLM;
- цикл `пользователь → LLM → MCP tool → API → tool result → LLM`;
- безопасное ограничение данных, доступных агенту.

## Реализация

- `server.py` — MCP-сервер и инструмент `search_recordings`;
- `main.py` — MCP-клиент и агент DeepSeek;
- MusicBrainz — внешний API без ключа;
- `.env` в корне — хранение `DEEPSEEK_API_KEY` вне Git.

Инструмент принимает:

- `query` — поисковый запрос MusicBrainz;
- `limit` — от 1 до 10 результатов.

Ответ содержит только нужные агенту поля: ID записи, название, исполнитель, дата первого релиза, релизы и score. Полный ответ внешнего API в контекст модели не отправляется.

## Установка и запуск

Из корня репозитория:

```powershell
python -m pip install -r projects/week-4-task-2/requirements.txt
python projects/week-4-task-2/main.py
```

Запуск с другим запросом:

```powershell
python projects/week-4-task-2/main.py --prompt "Найди три записи Kraftwerk и сравни даты релиза"
```

Без `--prompt` запускается готовый демонстрационный запрос про Daft Punk.

## Ожидаемый результат

```text
MCP connected: ...
Available tools: search_recordings
User: Find up to three MusicBrainz recordings matching Aerodynamic by Daft Punk...

Tool call: search_recordings(...)
Tool result: 3 recordings

Assistant: ...
```

## Проверка

```powershell
Push-Location projects/week-4-task-2
python -m unittest -v
Pop-Location
```

Юнит-тесты не обращаются к сети: проверяют нормализацию ответа MusicBrainz и ограничение `limit`. Полная проверка задания — запуск `main.py`, где должны быть видны MCP-подключение, автоматический tool call, результат инструмента и итоговый ответ модели.

## Сценарий видео

1. Показать `server.py`: декоратор `@server.tool`, описание и параметры `query`/`limit`.
2. Показать в `main.py` передачу MCP-схемы в DeepSeek и обработку `tool_calls`.
3. Запустить `python projects/week-4-task-2/main.py`.
4. Показать строки `MCP connected`, `Available tools` и `Tool call`.
5. Показать количество записей от MusicBrainz и финальный ответ агента.
6. Подвести итог: модель сама выбрала инструмент, MCP-сервер вызвал внешний API, результат вернулся модели и был использован в ответе.

Не открывать корневой `.env` во время записи.

## Вывод

MCP отделяет бизнес-действие от конкретного агента: MusicBrainz API скрыт за узким инструментом с понятной схемой. Модель не получает произвольный сетевой доступ и не знает детали HTTP-запроса — она видит только разрешённое действие и нормализованный результат. Такой контракт проще переиспользовать, тестировать и ограничивать, чем передавать модели полную документацию внешнего API.
