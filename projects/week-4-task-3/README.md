# День 18 — планировщик и фоновые задачи

MCP-сервер создаёт периодические задания для MusicBrainz, хранит расписание и результаты в SQLite и выполняет сбор данных фоновым worker-потоком. Клиент показывает две автоматические итерации, читает сохранённые сводки и останавливает расписание.

## Цель задания

Сделать MCP-инструмент, который не ограничивается одним синхронным вызовом:

1. сохраняет расписание;
2. продолжает работу в фоне;
3. периодически собирает данные;
4. сохраняет каждый результат;
5. возвращает последнюю агрегированную сводку.

## Что изучаем

- фоновые worker-процессы;
- периодическое выполнение без внешнего scheduler-фреймворка;
- хранение состояния и истории в SQLite;
- разделение создания задания и чтения результата;
- отмену будущих запусков без удаления истории;
- устойчивость фоновой задачи к ошибке внешнего API.

## Реализация

MCP-сервер предоставляет три инструмента:

- `schedule_artist_digest` — создаёт периодическое задание;
- `get_latest_digest` — возвращает последнюю сохранённую сводку;
- `cancel_schedule` — останавливает будущие запуски.

Worker каждые 0,5 секунды проверяет просроченные задания. Для каждого задания он получает до пяти записей MusicBrainz, строит короткую сводку, сохраняет исходные нормализованные данные и summary в SQLite. Ошибка API тоже сохраняется как результат запуска, поэтому цикл не падает.

Файл базы создаётся в `projects/week-4-task-3/data/` и не попадает в Git.

## Установка и запуск

```powershell
python -m pip install -r projects/week-4-task-3/requirements.txt
python projects/week-4-task-3/main.py
```

Другой исполнитель и интервал:

```powershell
python projects/week-4-task-3/main.py --artist "Kraftwerk" --interval 10
```

Для видео используется интервал 5 секунд. Для реальной постоянной работы следует задать большее значение и держать MCP-процесс запущенным на VPS или локальной машине.

## Проверка

```powershell
Push-Location projects/week-4-task-3
python -m unittest -v
Pop-Location
```

Живой запуск должен показать:

1. MCP-подключение и три инструмента;
2. созданный schedule ID;
3. две разные записи `Run #...`;
4. сообщение о чтении данных из SQLite;
5. успешную отмену расписания.

## Сценарий видео

1. Показать SQLite-схему и `scheduler_loop` в `server.py`.
2. Показать три декоратора `@server.tool`.
3. Запустить `python projects/week-4-task-3/main.py`.
4. Показать создание расписания и первую сводку.
5. Дождаться второй автоматической сводки с новым `run_id`.
6. Показать отмену задания и объяснить, что история остаётся в SQLite.

## Вывод

MCP-инструмент может запускать долгоживущее действие, а не только отвечать в рамках одного запроса. Расписание и результаты отделены от памяти процесса и сохраняются в SQLite, поэтому данные переживают перезапуск. Короткий пятисекундный интервал нужен только для видео; та же схема подходит для часовых или суточных сводок при постоянном запуске сервера.
