# День 19 — композиция MCP-инструментов

Один MCP-сервер предоставляет три независимых инструмента. Клиент автоматически выполняет их как pipeline: ищет записи MusicBrainz, передаёт нормализованные данные в генератор Markdown и сохраняет готовый отчёт.

## Цель задания

Проверить не отдельный tool, а согласованную цепочку:

```text
search_recordings → summarize_recordings → save_report
```

Результат первого шага становится входом второго, а Markdown второго — входом третьего. Ручное копирование данных между командами не требуется.

## Что изучаем

- несколько tools внутри одного MCP-сервера;
- композицию небольших инструментов;
- передачу структурированных данных между шагами;
- разделение получения, обработки и сохранения;
- проверку промежуточных результатов;
- ограничение файловой операции разрешённой директорией.

## Реализация

- `search_recordings` принимает исполнителя, название и лимит, затем возвращает нормализованные записи MusicBrainz;
- `summarize_recordings` принимает результат поиска и создаёт Markdown-таблицу;
- `save_report` принимает Markdown, нормализует имя файла и сохраняет его только в `data/reports/`;
- `main.py` последовательно вызывает все три инструмента и показывает, что передано между этапами.

Папка `data/` исключена из Git, поэтому демонстрационные отчёты не засоряют репозиторий.

## Установка и запуск

```powershell
python -m pip install -r projects/week-4-task-4/requirements.txt
python projects/week-4-task-4/main.py
```

Другие входные данные:

```powershell
python projects/week-4-task-4/main.py --artist "Kraftwerk" --title "The Model" --limit 5
```

## Проверка

```powershell
Push-Location projects/week-4-task-4
python -m unittest -v
Pop-Location
```

Живой запуск должен вывести три пронумерованных шага и завершиться строкой:

```text
Pipeline completed: search -> summarize -> save.
```

После запуска отчёт находится в `projects/week-4-task-4/data/reports/`.

## Сценарий видео

1. Показать в `server.py` три декоратора `@server.tool` и их входные схемы.
2. Показать в `main.py`, как `search` передаётся в `summarize`, а `markdown` — в `save`.
3. Запустить `python projects/week-4-task-4/main.py`.
4. Показать три последовательных шага в консоли.
5. Открыть созданный Markdown-файл и показать таблицу результатов.
6. Подвести итог: цепочка выполнена автоматически, формат данных между инструментами сохранился.

## Вывод

Несколько узких MCP-инструментов проще проверять и переиспользовать, чем один универсальный инструмент. Явные структурированные результаты делают границы pipeline наблюдаемыми: на каждом шаге видно количество записей, созданный Markdown и путь сохранённого файла. Файловый инструмент не принимает произвольный путь, поэтому агент не может записать отчёт за пределами выделенной директории.
