# День 21 — сценарий записи

Цель: показать превращение документации в локальный индекс, сравнить fixed-size и structural chunking. Изучаем чанки, embeddings, метаданные.

## До записи

- Открыть терминал в корне `ai-advent-challenge`, README и `main.py` этого дня.
- Проверить доступность Ollama и модели `embeddinggemma`.
- Не показывать `.env`, токены, персональные данные и полный внутренний экспорт. Для публичного видео использовать разрешённые фрагменты или обезличенный корпус.
- Подтвердить объём корпуса: минимум 20–30 страниц или сопоставимый объём текста. Число файлов само по себе объём не доказывает.

## На видео, 3–5 минут

1. «День 21: строю два индекса одной базы знаний. Embeddings вычисляются локально».
2. Показать структуру Markdown-корпуса, объём и функции `fixed_chunks` / `structured_chunks`.
3. Выполнить из корня репозитория:

   ```powershell
   python projects/week-5-task-1/main.py
   ```

4. Показать начало и завершение индексации. Длинное ожидание можно вырезать, обозначив монтаж.
5. Сравнить фактические `chunks`, `sources`, `avg_words` двух стратегий. Не подставлять старые числа из README как результат нового запуска.
6. Открыть по одному безопасному фрагменту `data/index-fixed.json` и `data/index-structure.json`: `source`, `title`, `section`, `chunk_id`, `strategy`, embedding и его размерность.
7. Показать границу смыслового раздела: fixed-size может разрезать её, structural сохраняет заголовок.

## Приёмка

- [ ] Обе стратегии использовали один корпус.
- [ ] Два индекс-файла созданы, vectors непустые и одинаковой размерности.
- [ ] Метаданные позволяют найти исходный документ и раздел.
- [ ] Сравнение основано на показанном запуске, объём корпуса подтверждён.

Вывод для озвучивания: «Fixed-size даёт равномерные фрагменты; structural лучше сохраняет смысловые разделы. Оба индекса готовы для поиска».
