# День 22 — первый RAG-запрос

Один вопрос отправляется в DeepSeek двумя способами: без внутреннего контекста и с фрагментами, найденными в structural-индексе Дня 21.

## Что изучаем

- semantic search по embeddings;
- cosine similarity и `top-K`;
- сборку RAG-промпта;
- grounded-ответы и ссылки на источники;
- сравнение LLM без RAG и с RAG.

## Подготовка

Сначала построить индекс:

```powershell
python projects/week-5-task-1/main.py
```

Ollama должен быть запущен, `embeddinggemma` загружена, а `DEEPSEEK_API_KEY` задан в корневом `.env`.

## Запуск

```powershell
python projects/week-5-task-2/main.py
```

Другой вопрос:

```powershell
python projects/week-5-task-2/main.py --question "Когда удалять старую поставку при переносе каталога?"
```

Проверить retrieval на всех контрольных вопросах без десяти вызовов LLM:

```powershell
python projects/week-5-task-2/main.py --evaluate
```

Программа выводит:

1. вопрос;
2. ответ без RAG;
3. ответ с RAG;
4. пять найденных чанков, similarity score и источники.

## Контрольные вопросы

Файл `control_questions.json` содержит 10 реальных вопросов, ожидаемое содержание и ожидаемый раздел документации. Он нужен для ручной проверки полноты ответа и правильности retrieval.

Фактический baseline на structural-индексе: `hit@5 = 9/10`.

## Проверка

```powershell
python -m unittest discover projects/week-5-task-2 -v
```

## Что показать на видео

1. Показать два режима в `main.py`.
2. Показать `control_questions.json`.
3. Запустить один внутренний вопрос.
4. Сравнить ответы без RAG и с RAG.
5. Показать найденные источники и similarity score.
6. Объяснить: без RAG модель не знает внутренних правил; с RAG отвечает по документации и сохраняет оговорки `[Нужно подтвердить]`.

## Вывод

RAG даёт модели только релевантные фрагменты внутренней базы. Ответ становится проверяемым: рядом видны документы, разделы и similarity score. Без RAG модель способна дать общий или выдуманный ответ, особенно на внутренние вопросы GOOST.
