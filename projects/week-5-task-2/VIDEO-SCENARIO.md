# День 22 — сценарий записи

Цель: сравнить один вопрос без RAG и с RAG. Изучаем semantic search, cosine similarity, top-K и сборку контекста.

## До записи

Нужны structural-индекс Дня 21, работающий Ollama и ключ DeepSeek в окружении процесса. Ключ не показывать. Открыть `control_questions.json`: десять вопросов с ожиданиями и источниками.

## На видео, 4–6 минут

1. «День 22: модель получает один вопрос сначала без внутренней базы, затем с найденным контекстом».
2. Показать десять контрольных вопросов, поля `expected` и `source`.
3. Запустить:

   ```powershell
   python projects/week-5-task-2/main.py --question "Когда удалять старую поставку при переносе каталога?"
   ```

4. Сравнить `WITHOUT RAG` и `WITH RAG`. Проверить, что RAG сохраняет условие: сначала повторная доставка и проверка привязки статистики, потом удаление старой поставки.
5. Показать найденные чанки, score, документ и раздел. Сверить ответ с исходным фрагментом.
6. Повторить на вопросе «Какую ссылку отправить артисту для обращения в поддержку?». Проверить точную ссылку, не похожий адрес.
7. Запустить проверку retrieval:

   ```powershell
   python projects/week-5-task-2/main.py --evaluate
   ```

8. Показать десять строк и итог. Важно: `hit@K` здесь проверяет попадание документа, а не качество ответа или точность раздела. Для полного сравнения пройти все десять вопросов в обоих режимах и сверить ответы с `expected` вручную; сохранить результаты отдельно, без публикации внутренних текстов.

## Приёмка

- [ ] Один и тот же вопрос показан в обоих режимах.
- [ ] Есть десять вопросов с ожиданиями и источниками.
- [ ] Для десяти ответов отмечены полнота, ошибки и источник; retrieval не выдан за оценку генерации.
- [ ] Не утверждаем, что без RAG ответ обязательно неправильный: оцениваем фактические ответы.

Вывод: «RAG добавляет внутренние правила и проверяемые источники. Попадание документа в top-K ещё не гарантирует правильный ответ».
