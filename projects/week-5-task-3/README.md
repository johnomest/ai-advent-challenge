# День 23 — фильтрация и реранкинг RAG

Проект улучшает поиск Дня 22: переписывает вопрос в поисковый запрос, получает расширенный `top-N`, отбрасывает слабые результаты, пересчитывает релевантность и убирает дубли разделов.

## Что изучаем

- query rewriting;
- разницу между `top-N` кандидатов и итоговым `top-K`;
- similarity threshold;
- heuristic reranking;
- дедупликацию источников;
- сравнение базового и улучшенного RAG.

## Алгоритм

```text
Вопрос
  → DeepSeek query rewrite
  → embeddings исходного и переписанного запросов
  → два vector search top-20
  → объединение кандидатов по лучшему score
  → threshold 0.30
  → 60% vector score + 30% lexical overlap + 10% source authority
  → дедупликация source + section
  → итоговый top-3
  → ответ DeepSeek
```

Реранкер намеренно сделан без дополнительной модели: для учебного корпуса достаточно прозрачной эвристики. Каноническая менеджерская документация получает приоритет, а `legacy/` — минимальный вес. Cross-encoder стоит добавлять только после измеримого провала на контрольных вопросах.

Фактическое сравнение на одном наборе:

```text
Day 22 baseline: hit@5 = 9/10
Day 23 improved: hit@3 = 10/10
```

1. Показать проблему Дня 22: правильный чанк найден, но рядом присутствуют нерелевантные технические фрагменты.

4. Сравнить `BASE RETRIEVAL` и `FILTERED AND RERANKED`.
5. Сравнить два ответа модели.
6. Подвести итог: второй этап поиска уменьшает шум и делает ответ точнее.

## Вывод

Один vector similarity недостаточен: близкие по теме документы могут отвечать на другой вопрос. Query rewrite добавляет полезные термины, threshold убирает слабые совпадения, reranking поднимает фрагменты с прямыми признаками ответа, а дедупликация не позволяет одному разделу занять весь контекст.
