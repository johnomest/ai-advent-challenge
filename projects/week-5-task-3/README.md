# День 23 — query rewrite, фильтрация и реранкинг

Улучшаем поиск по PDF **How to Get Hired** из Дня 21. Используем те же десять
вопросов и функцию ответа Дня 22. Новые зависимости не нужны.

## Что изучаем

- Query rewrite переводит вопрос в английский поисковый запрос с синонимами.
- Cosine similarity отсекает слабые совпадения.
- Локальный heuristic reranker сочетает embedding-score и совпадение слов.
- Метаданные студии помогают не приписывать чужие условия выбранной студии.

## Два режима

**Baseline:** исходный вопрос → embedding → top-5 → ответ.

**Improved:** исходный вопрос + rewrite → по top-20 для каждого → объединение
по chunk_id → threshold → фильтр названной студии → реранкинг → до top-5 → ответ.

Формула: `0.65 × cosine + 0.35 × IDF-weighted coverage` слов переписанного запроса.
Точные дубли текста удаляются. Несколько разных чанков одной страницы сохраняются.
Если ничего не прошло порог, код сообщает о недостатке контекста без вызова LLM
для improved-ответа. Слабыми результатами пустой список не дополняется.

Одинаковые модель, промпт ответа, temperature и итоговый top-K в обоих режимах.
Меняется только подготовка контекста. Это сравнение всего пайплайна, а не
изолированный эксперимент влияния каждого отдельного компонента.

## Запуск

Из корня репозитория с активированным `.venv`:

```powershell
python projects/week-5-task-3/main.py --with-answers
```

По умолчанию вопрос про образование в IV, порог `0.40`, `--top-n 20`, `--top-k 5`.
Индекс: `projects/week-5-task-1/data/how-to-get-hired-video/index-structure.json`.
Ollama с `embeddinggemma` должен работать; ключ DeepSeek читается из корневого
`.env` или окружения, без вывода в консоль.

```powershell
python projects/week-5-task-3/main.py --question "Какие работы и навыки Framestore ищет при просмотре портфолио?" --with-answers --threshold 0.40 --top-n 20 --top-k 5
```

Без активированного окружения замените `python` на `.\.venv\Scripts\python.exe`.
Для другого индекса есть `--index`, для модели — `--model`.

## Сравнение десяти вопросов

```powershell
python projects/week-5-task-3/main.py --evaluate --with-answers --output projects/week-5-task-3/data/evaluation-answers.json
```

Вопросы и ожидания берутся из `../week-5-task-2/control_questions.json`.
Полный прогон: до **30 вызовов DeepSeek** — десять rewrite и двадцать ответов.
Без `--with-answers` остаются десять облачных rewrite; текст PDF не отправляется.
С флагом выбранные фрагменты отправляются для ответов, согласно разрешению
пользователя. Embeddings, фильтрация и реранкинг локальные.

Вывод показывает rewrite, число кандидатов после каждого этапа, score, страницы,
chunk_id и два ответа. JSON сохраняется после каждого завершённого вопроса;
завершённый полный прогон дополнительно содержит `summary`.
`data/` исключена из Git, книга и фрагменты не публикуются.

`page_hit` — найдена ожидаемая страница; `evidence_hit` — внутри одного чанка
найдены контрольные термины. **Это не точность ответа.** Ответы проверяем вручную.

## Ограничения

Порог `0.40` — стартовое значение для этой книги и `embeddinggemma`, не универсальный
порог релевантности. Score не является вероятностью правильного ответа.
Проверяем поведение на вопросах вне базы и при смене корпуса.

Принадлежность к студии извлекается из заголовка `STUDIO + domain` и наследуется
следующими страницами. Это эвристика для последовательных интервью этой книги.
Метаданные добавляются одинаково в обоих режимах; сохранённый индекс не меняется.
Для другого корпуса нужны явные метаданные разделов при индексации.
Фильтр срабатывает только на точное название студии из исходного вопроса, не на
русскую транслитерацию или местоимение. Он может исключать полезные межстудийные
сравнения. Rewrite также может потерять смысл; исходный запрос поэтому сохраняется
во втором поиске. Ответ LLM всё ещё требует проверки источников.
