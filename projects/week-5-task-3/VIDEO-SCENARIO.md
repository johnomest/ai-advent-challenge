# День 23 — сценарий записи

Цель: показать поиск до и после query rewrite, фильтра и reranking. Изучаем очистку контекста и различие top-N / top-K.

## На видео, 4–6 минут

1. «День 23: после первого поиска отбираю фрагменты, непосредственно отвечающие на вопрос».
2. Показать настройки: кандидаты top-20, результат top-3, threshold 0.30. Показать формулу: 60% vector score, 30% lexical overlap, 10% source authority; дедупликация по документу и разделу.
3. На том же вопросе Дня 22 выполнить:

   ```powershell
   python projects/week-5-task-3/main.py --question "Когда удалять старую поставку при переносе каталога?" --top-n 20 --top-k 3 --threshold 0.30
   ```

4. Показать `REWRITTEN QUERY`, `BASE RETRIEVAL`, `FILTERED AND RERANKED`, затем оба ответа.
5. Сверить сохранение условия удаления старой поставки. Объяснить, какие лишние разделы исчезли; если отличий нет — показать это честно.
6. Сравнить десять вопросов на одном неизменном индексе:

   ```powershell
   python projects/week-5-task-2/main.py --evaluate --top-k 3
   python projects/week-5-task-3/main.py --evaluate --top-n 20 --top-k 3 --threshold 0.30
   ```

7. Показать оба фактических итога. Одинаковый top-K нужен для честного сравнения; прежние `hit@5` и `hit@3` из README не являются контролируемым сравнением. Проверка считает документы, поэтому дополнительно сверить правильные разделы и смысл ответов.

## Приёмка

- [ ] Корпус и вопросы одинаковые, итоговый top-K одинаковый.
- [ ] Видны исходный вопрос, переписанный запрос и результаты обоих режимов.
- [ ] Показаны порог и число кандидатов до/после отбора.
- [ ] Улучшение оценивается по источнику и ответу, не только по score.

Дополнение рабочего бота: тематические названия блоков, отдельный поиск по менеджерской базе и сборка связанной процедуры. Это дальнейшая эволюция, не замена сравнения учебных режимов.
