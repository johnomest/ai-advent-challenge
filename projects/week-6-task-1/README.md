# День 26 — запуск локальной LLM

## Цель

Убедиться, что локальная генеративная модель работает без облачного API,
отвечает через CLI/HTTP и обрабатывает минимум три запроса разной сложности.
Это проверка запуска, не гарантия качества модели. RAG здесь не добавляется.

Используем уже установленную **gemma4:12b-it-qat** в Ollama. Повторная установка
не нужна. Размер по `/api/tags`: 7 151 003 754 байт (около 7.15 GB).
Рабочий контекст 8192, temperature 0, thinking отключён, максимум 768 выходных токенов.

## CLI

```powershell
ollama list
ollama run gemma4:12b-it-qat
```

В интерактивном чате Ollama:

```text
/set parameter num_ctx 8192
Ответь одним словом: какая столица Франции?
/bye
```

Это команда чата Ollama, не SQL. Отдельно проверить загрузку:

```powershell
ollama ps
```

Если Ollama остановлен, запустите приложение Ollama или `ollama serve` в отдельном
терминале. Если модель отсутствует: `ollama pull gemma4:12b-it-qat`.

## HTTP: три запроса

Из корня репозитория, `.venv` активировано:

```powershell
python projects/week-6-task-1/main.py
```

Без активированного окружения: `.\.venv\Scripts\python.exe` вместо `python`.
Используется только стандартная библиотека. Ключи, `.env`, DeepSeek не нужны.
Адрес ограничен loopback, системный HTTP-прокси отключён для запросов.
Вызовы: `/api/tags`, `/api/version`, `/api/chat`, `/api/ps`.

1. Простой факт: столица Франции, ожидается «Париж».
2. Структурированный JSON: артист, дата релиза и бюджет. Ожидание:
   Astin Ray, 2026-10-12, 108000.
3. Аналитика: оптимальный выбор неделимых проектов при лимите 8 часов.
   Ожидание: A+B, 8 часов, прибыль 210. Условия и все вводные выводятся в консоль.

Видны вопрос, полный ответ, время, токены/с, признак обрыва и результат проверки.
Результат сохраняется после каждого ответа в `data/results.json`, исключённой
из Git. Код возврата 1 при провале контрольного ответа означает ошибку качества
или формата, а не обязательно проблему запуска Ollama.

Свой запрос:

```powershell
python projects/week-6-task-1/main.py --question "Объясни разницу между RAG и обучением модели в трёх предложениях."
```

Параметры: `--model`, `--num-ctx`, `--max-tokens`, `--url`, `--output`.
Каждый запрос независим: история предыдущего вопроса не передаётся.
Для холодного старта время включает загрузку весов; tokens/s вычисляется только
по `eval_count / eval_duration`, не по общему времени запроса.

## Проверки

```powershell
python -m unittest discover projects/week-6-task-1 -v
```

Три теста: только локальный адрес, эталонные ответы и отклонение ошибок чисел,
дат, дублированных проектов и невалидного JSON.
