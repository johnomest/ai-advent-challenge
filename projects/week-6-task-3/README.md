# День 28 — локальный CLI-чат с RAG

Цель: полностью локальный RAG, от поиска до генерации. Изучаем разделение embedding
модели и генеративной модели, повторное использование индекса и проверку качества.

Берём индекс PDF How to Get Hired из Дня 21 (Неделя 5; «Неделя 6» в задании —
опечатка). Переиндексация не нужна: 63 структурных чанка, embeddinggemma, 768 измерений.

Пайплайн: вопрос + недавний диалог → локальный английский rewrite через Qwen 9B →
embeddinggemma для вопроса и rewrite → cosine top-20 для каждого → порог 0.4,
фильтр студии и heuristic reranking из Дня 23 → top-5 → ответ Qwen 9B с контекстом.
Оба LLM-этапа используют локальный llama.cpp, embeddings — локальную Ollama. Импортированные
функции облачного API прошлой недели не вызываются.

Rewrite получает тему книги, чтобы различать письмо работодателю и художественную
работу. Follow-up сохраняет название студии и контекст найма из недавнего диалога.
В контекст ответа входят текст, страница, chunk_id и название студии.
Это помогает соблюдать границы интервью; точность всё равно проверяем по PDF.

## Запуск из корня репозитория

Сначала запустить Qwen-сервер из Дня 27 в отдельном PowerShell-терминале:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local-qwen.ps1
```

Ollama также должна работать с установленной `embeddinggemma`.
Если Ollama не запущена, открыть её приложение или выполнить `ollama serve`
в отдельном терминале. Затем запустить чат:

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-3/main.py
```

Индекс по умолчанию:
`projects/week-5-task-1/data/how-to-get-hired-video/index-structure.json`.
Его нет в Git: сначала построить День 21 либо перенести свой локальный индекс.
Генерация: `Qwen3.5-9B-Q8_0` на `http://127.0.0.1:8080`.
Embedding: прежняя `embeddinggemma` на `http://127.0.0.1:11434`.
Смена генеративной модели не меняет embedding-пространство индекса.

Один вопрос:

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-3/main.py --question "Нужен ли диплом, чтобы устроиться в Framestore?"
```

Команды: `/reset`, `/exit`. Память ограничена так же, как в Дне 27.
Параметры: `--index`, `--top-k`, `--threshold`, `--model`, `--max-tokens`,
`--url` для llama.cpp и `--embedding-url` для Ollama. Оба адреса — только loopback.

Источники показываются отдельным блоком из метаданных реально найденных чанков.
Модель также получает инструкцию цитировать chunk_id, но соответствие каждой
фразы источнику не проверяется автоматически. Это не строгий validator Дня 24.
При пустом контексте генерация ответа пропускается, выводится «Не знаю».
Similarity и наличие источника сами по себе не доказывают правильность ответа.

## 10 контрольных вопросов и сравнение

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-3/main.py --evaluate
```

Берёт те же 10 вопросов и ожидания из Дня 22. Для каждого выводит локальный ответ,
источники и полное время (rewrite + embedding + поиск + ответ). Если сохранён
`projects/week-5-task-2/data/evaluation-answers.json`, выводит рядом прежний ответ
DeepSeek. Новых облачных запросов нет.

Результаты: `data/evaluation.json`, вне Git. Для отдельного прогона передать
`--output projects/week-6-task-3/data/evaluation-my-run.json`.
JSON хранит ответы, источники, rewrite, ожидания, архивный ответ DeepSeek,
параметры и тексты обоих системных промптов. Качество сравниваем вручную с `expected`.
Это практическое сравнение двух систем: retrieval различается; оно не изолирует
качество самих моделей. Время DeepSeek раньше не записывалось — честного численного
сравнения скорости нет. `completed` показывает успешность этого запуска, не
доказательство долговременной стабильности. Повторить тест для повторяемости.

## Проверка

### Автотест для записи видео

При работающих Qwen и Ollama, из корня проекта:

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-3/main.py --video-test
```

Без ввода вопросов выполняет все 10 независимых запросов. Для каждого показывает
ожидание, новый ответ Qwen, архивный ответ `deepseek-v4-flash`, источники,
полное время и проверки найденной страницы, терминов и chunk_id.
В конце — выводы о скорости, завершении запросов, качестве и различиях с облаком.

Сохраняет `data/video-test.json` и читаемый `data/video-test.md`. Обычный
`data/evaluation.json` не меняет. Можно задать другой JSON через `--output`;
Markdown сохраняется рядом. Следующий запуск заменяет эти файлы.

Для сравнения нужен облачный архив Дня 22 с ответами на все 10 вопросов.
Новых облачных вызовов нет. Ошибки API или провал проверки источников дают
код выхода 1; частичный по смыслу ответ отдельно отмечается ручной оценкой.

Сохранённая ручная оценка переносится только при совпадении ответа, источников,
ожидания, модели, документа, промптов и настроек с проверенным прогоном.
Сравнительные замечания также требуют совпадения облачного ответа и модели.
Изменённые ответы или отсутствие локального файла ручной проверки означают
«нужна ручная проверка». Автотест не выдаёт проверку ссылок за оценку смысла.
