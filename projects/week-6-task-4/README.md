# День 29 — оптимизация локальной Qwen 9B

Продолжение RAG Дня 28: тот же PDF How to Get Hired, 63 чанка и embeddinggemma.
Rewrite и генерация остаются локальными. Новые зависимости и облачные вызовы не нужны.

Выбранный профиль: Qwen3.5-9B Q4_K_M, контекст 8192, temperature 0,
max_tokens 768, thinking выключен. Промпт требует название студии, источник,
английскую цитату целого ответа и русский перевод с условиями и последним советом.
Rewrite использует прежний промпт и лимит 1536. Индекс не меняется.

## Запуск

Из корня проекта в Windows PowerShell, отдельный терминал:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local-qwen.ps1 -Quantization Q4_K_M-requant -ContextSize 8192
```

Если порт 8080 занят, сначала остановить текущий Qwen-сервер в его терминале.
Ollama должна работать с установленной embeddinggemma. Затем:

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-4/main.py
```

Команды `/reset`, `/exit`; память — последние пять ходов текущего процесса.
Один вопрос:

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-4/main.py --question "Как студия IV относится к художественному образованию кандидата?"
```

Дни 27–28 и профиль `--preset baseline` используют исходный Q8_0.
Для них запустить `scripts/start-local-qwen.ps1` без дополнительных параметров.
Чат проверяет alias модели и реальный размер контекста сервера.

## Автотест для видео

При работающих Qwen и Ollama:

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-4/main.py --video-test
```

Выполняет десять независимых вопросов до и после оптимизации. Каждый профиль
получает полный RAG: rewrite → embeddings → поиск → генерация. Перед измерением
сервер запускается заново и прогревается; embedding-модель также прогревается.
Во время теста не отправлять другие запросы на эти серверы.

Тест временно перезапускает только проверенный сервер проекта на 127.0.0.1:8080;
в `finally` возвращает его исходные аргументы. Поддерживается Windows Python
из `.venv/Scripts/python.exe`, в том числе при запуске из WSL.
При принудительном завершении Python восстановление выполнить запуском скрипта вручную.

Файлы `data/before-after.json`, `data/before-after.md` содержат ответы, ожидания,
источники, параметры, SHA-256, время полного запроса, скорость декодирования
и измерения памяти. Следующий запуск заменяет их. JSON и модели исключены из Git.
Ручная оценка из `data/manual-quality.json` применяется только при совпадении
ответов, источников, моделей, документа и настроек. Новые ответы требуют проверки.
Ошибка запроса или отсутствующая ссылка на найденный источник дают код выхода 1.
Проверка наличия ссылки не доказывает, что она подтверждает все утверждения.

## Эксперименты по одному фактору

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-4/main.py --benchmark
```

Сначала фиксируется найденный контекст для каждого контрольного вопроса.
Затем отдельно сравниваются temperature 0.3, max_tokens 512, контекст 4096,
два варианта промпта и Q4_K_M с исходным Q8_0. Завершает тест выбранный профиль
и его повтор. Здесь измеряется генерация на одинаковых фрагментах; это время
нельзя смешивать со временем полного RAG из `--video-test`.
Сохранение: `data/benchmark.json` и отдельные JSON каждого профиля.

Контекст 4096 реально выделяется новым процессом llama.cpp; изменение лимита
ответа само по себе окно контекста не уменьшает. `seed=42`, `cache_prompt=false`;
повторяемость проверена на этом runtime, а не обещана для любого оборудования.

## Происхождение Q4

Исходный Q8_0 сохранён. Q4 получен повторным квантованием Q8_0 существующим
llama-quantize b11514; это может добавлять потери по сравнению с квантованием FP16.
Команда из корня проекта, при необходимости воспроизвести:

```powershell
& ".local-archive/models-cleanup-20261011-3UZ0qB/llama-b11514-cuda12.4/llama-quantize.exe" --allow-requantize --max-buffer-size 512 "models/Qwen3.5-9B-Q8_0/Qwen_Qwen3.5-9B-Q8_0.gguf" "models/Qwen3.5-9B-Q4_K_M-requant/Qwen3.5-9B-Q4_K_M-requant.gguf" Q4_K_M 8
```

До запуска создать целевую папку. Не перезаписывать исходный GGUF.
Модели, runtime из локального архива и индекс нужно иметь локально;
репозиторий их не загружает автоматически.
