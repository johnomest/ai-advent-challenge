# День 30 — приватный AI-сервис и Telegram-бот

Telegram → защищённый HTTP API на компьютере → очередь → локальный RAG
с Qwen3.5-9B-Q4_K_M-requant и embeddinggemma. Используется прежний индекс
How to Get Hired. Новые библиотеки не нужны: Python standard library.

Генерация, rewrite и поиск локальны. Сообщения бота проходят через Telegram.
Внешний пользователь обращается к боту через интернет; порты компьютера
открывать не требуется. Схема соответствует одобренному варианту из обсуждения
задания: [сообщение 5027](https://t.me/c/3751017277/5027).

## Запуск из корня проекта

Qwen в отдельном терминале Windows PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local-qwen.ps1 -Quantization Q4_K_M-requant -ContextSize 8192
```

Ollama должна работать с установленной embeddinggemma. В `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=<токен от BotFather>
TELEGRAM_ALLOWED_USER_IDS=
```

Токен уже внесён пользователем. Не публиковать `.env`: он исключён из Git.
`LOCAL_AI_API_TOKEN` генерируется автоматически при первом запуске и сохраняется
в `.env` атомарной заменой файла. Существующие переменные сохраняются.
В stdout токены Telegram и HTTP API не выводятся.

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-5/main.py
```

Оставить терминал открытым. HTTP API слушает **127.0.0.1:8090**;
llama.cpp — **127.0.0.1:8080**. Сервер проверяет alias Q4, контекст 8192,
один слот и локальность embedding-модели. Q8-профиль для этого задания не подходит.
При запуске второго экземпляра порт будет занят; Telegram polling также допускает
только один активный процесс для этого токена. Завершение — `Ctrl+C`.

При первом запуске в терминале появится ссылка `https://t.me/omest_bot?start=...`.
Открыть её в Telegram и нажать Start: этот аккаунт становится владельцем.
Ссылка одноразовая, действует десять минут; не передавать её другим.
После истечения срока перезапустить сервис для новой ссылки.
Аккаунт владельца хранится в `data/owner.json`, вне Git; следующий запуск
привязку не требует. Состояние привязано к конкретному bot ID.

Дополнительные пользователи: записать числовые ID через запятую в
`TELEGRAM_ALLOWED_USER_IDS` и перезапустить сервис. Неразрешённый пользователь
получает свой ID и сообщение о закрытом доступе; модель не вызывается.
Если ссылка привязки не открылась, свой ID также можно добавить в эту переменную
и перезапустить сервис. Для текущего аккаунта доступ уже сохранён.
Пустая переменная разрешает только владельца. Группы, каналы и сообщения
других ботов игнорируются.

## Работа с телефона

Бот: `https://t.me/omest_bot`. Вопросы по книге: диплом, портфолио, собеседования,
повторные письма; можно уточнять «эта студия». Команды:

- `/start`, `/help` — краткая справка;
- `/reset` — очистить свою историю;
- `/id` — свой Telegram ID.

У каждого аккаунта отдельная история. Пока готовится ответ, нужно дождаться его
перед следующим вопросом. Бот показывает ответ, время и найденные источники.
Длинные сообщения разделяются на части с учётом Unicode; Markdown не исполняется.
Наличие chunk_id ещё не доказывает точность всей цитаты: ограничения Дня 29 сохраняются.

Для демонстрации интернет-доступа можно использовать телефон с мобильным
интернетом. Компьютер с моделью и ботом должен оставаться включённым.
Одновременно не запускать измерения Дня 29: они перезапускают Qwen между Q8 и Q4.

## Ограничения сервиса

- Одна GPU-задача выполняется за раз; очередь — до восьми ожидающих задач.
- Один незавершённый вопрос на сессию; повтор до ответа получает HTTP 409.
- Шесть вопросов за скользящие 60 секунд на сессию; дальше HTTP 429.
  `/reset` не обнуляет счётчик запросов.
- Вопрос: 1–1200 символов; JSON-body до 16 КиБ; до 16 соединений к HTTP API.
- История: последние пять ходов; до 128 сессий, неактивные удаляются через 30 минут.
- Реальное окно контекста: 8192 токена, выход: до 768. До генерации применяется
  chat template и токенизатор Qwen; вместе с резервом ответа превышение отвергается.
- Каждый модельный/embedding HTTP-вызов ограничен 30 секундами. Срок запроса с
  очередью — 120 секунд; просроченный ответ не изменяет историю. HTTP-клиент получает
  таймаут без ожидания всех последующих задач.
- История обновляется только при успешном завершении. Ошибка модели, неполный
  ответ или отмена сохраняют прежнюю историю.

Истории и задачи очереди находятся в RAM: после остановки сервиса не восстанавливаются.
Telegram offset сохраняется, чтобы уже принятые updates не повторялись после перезапуска;
это не журнал гарантированной доставки. При остановке во время ответа вопрос нужно
отправить заново. Владелец и allowlist восстанавливаются отдельно от истории.

## HTTP API

Все endpoints требуют `Authorization: Bearer <LOCAL_AI_API_TOKEN>`.
Без ключа — HTTP 401. Ключ из `.env` даёт доверенному локальному клиенту доступ
ко всем API-сессиям; Telegram использует его внутри процесса и не передаёт пользователям.
HTTP API не предназначен для прямой публикации без TLS и отдельной внешней защиты.

| Запрос | JSON | Результат |
|---|---|---|
| `GET /health` | — | Профиль, лимиты, очередь, счётчики |
| `POST /chat` | `question`, необязательный `session` | Ответ, источники, время, session, queue_seconds |
| `POST /reset` | `session` | Сброс истории этой сессии |

Без `session` API создаёт случайный `api:<uuid>`; для продолжения отправлять
возвращённый идентификатор. Собственные API session IDs: `api:<латиница/цифры/_/->`.
Telegram использует `telegram:<user_id>`; сессии разных пользователей не смешиваются.
Настройки модели, содержимое истории и промпт клиент не переопределяет.

Пример в PowerShell, без вывода ключа:

```powershell
$serviceKey = ((Get-Content .env | Where-Object { $_ -match '^LOCAL_AI_API_TOKEN=' } | Select-Object -Last 1) -replace '^LOCAL_AI_API_TOKEN=', '').Trim()
$serviceHeaders = @{ Authorization = "Bearer $serviceKey" }
Invoke-RestMethod http://127.0.0.1:8090/health -Headers $serviceHeaders
$serviceBody = @{ question = "Нужен ли студии IV отдельный resume?" } | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8090/chat -Method Post -Headers $serviceHeaders -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($serviceBody))
```

`--api-only` запускает сервис без Telegram; `--port` меняет локальный порт.
Автотест ниже использует стандартный 8090.

## Проверка и видео

При работающем сервисе:

```powershell
.\.venv\Scripts\python.exe projects/week-6-task-5/video_test.py
```

Проверяет auth, входные ограничения, чат и follow-up, отдельную сессию IV,
сброс, три одновременных запроса, очередь, rate limit и отказ вне корпуса.
Сохраняет ответы и результаты в `data/http-video-test.json` и `.md`, вне Git.
Ошибка проверки даёт код выхода 1. Проверки ключевых слов не заменяют ручную
оценку содержания. Доступ с телефона демонстрируется отдельно через бота.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s projects/week-6-task-5 -p "test_*.py"
```

Измерения: `results.md`. Сценарий записи: `VIDEO-SCENARIO.md`.
Telegram реализован через официальный [Bot API](https://core.telegram.org/bots/api#getupdates);
привязка — через [deep linking](https://core.telegram.org/bots/features#deep-linking).
Подсчёт контекста использует `/apply-template` и `/tokenize` из
[llama.cpp server](https://github.com/ggml-org/llama.cpp/tree/master/tools/server#api-endpoints).
