Проверка: **11 октября 2026**. Домашний компьютер Windows, локальные Qwen 9B
и embeddinggemma. Новый сервис использует выбранный профиль Дня 29:
**Qwen3.5-9B-Q4_K_M-requant**, llama.cpp b11514, контекст **8192**,
temperature **0**, выход до **768 токенов**. Корпус How to Get Hired и индекс
из 63 чанков сохранены; новые облачные модели и библиотеки не подключались.

## Что реализовано

`main.py` предоставляет HTTP API на `127.0.0.1:8090`: `/health`, `/chat`, `/reset`.
Каждый запрос требует Bearer-ключа; ключ автоматически сохраняется в игнорируемом
`.env`. Бот **@omest_bot** получает сообщения через Telegram long polling и
вызывает этот же API. Порты модели и приложения в интернет не открыты.
Сообщения проходят через Telegram, вычисления rewrite, embedding и ответа локальны.

Telegram допускает только владельца и явно разрешённые числовые ID. Привязка
владельца одноразовая, сохраняется для конкретного bot ID; личные ID и токены
не входят в этот отчёт. После сообщения пользователя о закрытом доступе его ID,
полученный в доверенном чате, добавлен в allowlist и сохранён как владелец.
Сервис перезапущен с этой конфигурацией.

У каждого пользователя своя история последних пяти ходов. Одна GPU-задача
выполняется за раз; до восьми ожидающих задач. Повторный незавершённый запрос
этой же сессии получает 409, переполненная очередь — 503. Лимит — шесть вопросов
за скользящие 60 секунд на сессию; сброс истории не обнуляет этот счётчик.
Вопрос ограничен 1200 символами, JSON — 16 КиБ, HTTP-соединения — 16,
сессии — 128 с удалением неактивных через 30 минут.

До генерации chat template и токенизатор Qwen проверяют фактическое число токенов
с резервом ответа. Превышение 8192 отклоняется. Модельные HTTP-вызовы имеют таймаут
30 секунд; срок запроса с очередью — 120 секунд. Ошибочный, отменённый или
просроченный запрос не сохраняет новый ход в историю. Таймаут не означает
принудительного прерывания уже запущенного вычисления на GPU.

## Проверки

**41 unit-тест прошёл:** День 27 — 9, День 28 — 10, День 29 — 7, День 30 — 15.
Проверены последовательное выполнение, раздельные истории, ошибки и отмены,
переполнение очереди, занятая сессия, rate limit без обхода через reset,
просроченная задача, остановка сервиса, HTTP-аутентификация и некорректный ввод,
одноразовая привязка владельца, allowlist, фильтрация групп, деление Unicode
сообщений и отсутствие токенов в сетевых ошибках.

**16/16 проверок реального HTTP API прошли**, процесс завершился с кодом 0.
Прогон включает 12 успешных запросов к локальному RAG, отдельный от них отказ
седьмому вопросу rate-limit сессии и проверку работоспособности после нагрузки.
Проверены:

- HTTP 401 без ключа; HTTP 400 для вопроса длиннее 1200 символов и попытки
  переопределить max_tokens;

  отдельная сессия IV и сброс истории;

- шесть разрешённых вопросов и HTTP 429 на седьмом;
- отказ на «Как приготовить борщ?» с пустым списком источников;
- доступность `/health` после прогона.

Дополнительно реальный токенизатор Qwen отклонил заведомо превышающий контекст
текст до вызова генерации. Это отдельная проверка от ограничения длины вопроса.

Telegram Bot API подтвердил имя **omest_bot**, webhook отсутствует, polling
запущен. Первое обращение с телефона корректно получило отказ при отсутствии

## Скорость и очередь

Время этого прогона, без холодного запуска модели. HTTP-время включает ожидание
и получение ответа; RAG-время включает rewrite, embeddings, retrieval и генерацию.

| Одновременный вопрос | HTTP, с | RAG, с | Ожидание очереди, с |
|---|---:|---:|---:|
| IV: художественное образование | 4,090 | 4,088 | 0,000 |
| GIANT ANT: как попасть в поле зрения | 7,393 | 3,303 | 4,094 |
| Framestore: рост нового сотрудника | 13,449 | 6,056 | 7,375 |

Последовательные вопросы: Framestore о дипломе — 6,019 с RAG;
follow-up о соцсетях — 6,348 с; IV о resume — 4,207 с.
При трёх подключениях одна GPU обрабатывает вопросы по очереди; это повышает
ожидание поздних запросов, сохраняя завершение всех трёх без смешения сессий.
