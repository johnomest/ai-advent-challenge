# День 10 — стратегии управления контекстом

Дата: 2026-09-11. Статус: **Done**.

## Задача

Отдельно реализовать задание Дня 10: сравнение Sliding Window, Sticky Facts и Branching в чат-интерфейсе. Исходный запрос: «/фича делаем два задания по отдельности. Используй подсказки если есть».

## Research

- Полная переписка хранится независимо от эффективного контекста; построение контекста не изменяет историю.
- Стратегия фиксируется для эксперимента; настройки доступны только до начала переписки.
- Sticky Facts — ограниченный JSON недоверенных данных, извлекаемый только из предыдущих фактов и текущего сообщения пользователя. Usage и стоимость извлечения учитываются отдельно.
- Branching — атомарные снимки A/B из выбранной контрольной точки, независимое продолжение веток, идемпотентные операции с проверкой владельца.
- UI сохраняет компактную визуальную систему GOOST и нативные элементы управления.

## План

1. Обновить схему хранения до v3 и добавить настройки стратегий, включая `window_turns`.
2. Реализовать построение контекста и API создания, изменения настроек и ветвления чатов.
3. Добавить управление стратегиями, фактами и ветками в Web UI.
4. Покрыть поведение тестами; проверить одинаковый сценарий для трёх стратегий на desktop и mobile.

- `projects/week-2-task-5/static/`: выбор стратегии, окно контекста, просмотр фактов и метрик, создание и переключение веток; защита от устаревших ответов preview и загрузки чата.

## Validation

Платформы: Backend Python и Web vanilla JS. Проверки выполнены отдельным worker в Microsoft Edge через Playwright с изолированным context. Desktop: 1440×1000; mobile: 390×844.

- 31 unittest — PASS; `node --check` — PASS.
- На каждой платформе отправлены одинаковые 12 сообщений для каждой стратегии.
- Sliding Window: полная переписка сохранена, эффективный контекст выбирает 2 из 12 ходов.
- Sticky Facts: ранние факты сохранены, город обновлён с Минска на Брест; HTML отображается безопасным текстом. Extraction usage/cost выделены отдельно. При отсутствии cache usage стоимость корректно остаётся `null`; расчёт при полном usage покрыт unittest.
- Branching: контекст включает 12 из 12 ходов. A/B создаются из checkpoint 6 с одинаковым префиксом, продолжаются независимо; родитель и lineage сохраняются после переключения и reload.
- Повтор запроса ветвления не создаёт дубли; изменённый checkpoint возвращает 409, чужой owner — 404.
- Устаревшие ответы preview и загрузки чата не изменяют активный экран.
- На desktop/mobile нет ошибок страницы и горизонтального переполнения. Context, browser и mock server закрыты; временная SQLite удалена.

Все шаги [персистентного E2E-сценария](day10-context-strategies-e2e-scenario.md) отмечены `[x]`.

## Проблемы и ограничения

Дефекты продукта и откаты стадий не выявлены. В проверочном harness уточнены два предположения: число пропущенных ходов равно `total_turns − selected_turns`; стоимость может быть `null` без cache usage.

Проверялся детерминированный mock provider, платные API не вызывались. Проверки подтверждают механику контекста и памяти; качество ответов и извлечения фактов живой LLM не оценивалось.
