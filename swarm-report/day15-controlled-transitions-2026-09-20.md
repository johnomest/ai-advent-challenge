# День 15 — контролируемые переходы задачи

Дата: 2026-09-20. Статус: **Done**.

Исходный запрос: `/фича давай день 15 со всеми вытекающими`.

## Задача и Research

День 14 содержал этапы задачи, но относительный переход `advance` позволял двигаться дальше без обязательных результатов. Вывод Research: порядок работы должен обеспечивать сервер; модель не должна самостоятельно менять этап или утверждать артефакты.

Согласованный объём: отдельный проект дня 15 на базе дня 14; явный целевой этап, таблица разрешённых переходов, сохранённый и утверждённый план, результат выполнения, отчёт проверки, ревизии и история. Сохранить память, профили, инварианты, owner isolation и существующий интерфейс GOOST. Ответ модели проверять по типу текущего этапа, не обещая проверки смысла всей прозы.

## План

1. Создать независимый `projects/week-3-task-5` с портом 8772 и отдельной SQLite.
2. Реализовать серверные условия переходов, артефакты, строгую схему действий и атомарную проверку `expected_revision`.
3. Добавить типизированный контракт модели и сохранить проверки инвариантов дня 14.
4. Расширить панель задачи: редакторы артефактов, утверждение, выбор целевого этапа, причины отказа, история и восстановление после конфликтов.
5. Проверить Backend/Web, подготовить README со сценарием записи на три минуты и итоговый отчёт.

## Реализовано

- `projects/week-3-task-5/main.py`: единая `TRANSITIONS`, `ContextStore.apply_task_action`, транзакция `BEGIN IMMEDIATE`, строгие поля и лимиты, `expected_revision`, история успешных действий, серверные причины запрета. Отказ не меняет задачу, историю, ревизию или `updated_at`.
- Переход planning → execution требует сохранённого утверждённого плана; execution → validation — результата; validation → done — статуса `passed` и непустого отчёта. Изменение плана снимает утверждение. Возврат validation → execution очищает результат и проверку, сохраняет план. Пауза допускает только `resume`; done закрывает task actions и новые сообщения модели.
- `projects/week-3-task-5/web.py`: API с явным `target_stage`, ответы 400/409/502, блокировка сообщений paused/done, сохранённые owner isolation и replay. Порт по умолчанию 8772; отдельная база схемы 5, без миграции данных прошлых дней.
- Контракт модели: `kind=plan/implementation/validation/completion` согласно этапу; неподходящий тип, лишние/дублирующиеся ключи и некорректный JSON отклоняются до сохранения хода. При активных инвариантах обязательны `language`, `architecture`, `budget`. Модель не сохраняет артефакты и не выполняет переходы.
- `projects/week-3-task-5/static/week.js`, `app.js`, `index.html`, `styles.css`: панель GOOST с артефактами, утверждением, всеми целевыми этапами, объяснениями запретов, ревизией и историей. Конфликт обновляет серверное состояние, сохраняя локальный черновик. Поздний ответ из чата A не перезаписывает состояние выбранного чата B.
- `projects/week-3-task-5/test_main.py`, `test_web.py`, `static/week.test.cjs`: проверки переходов, ошибок, атомарности и сохранённых функций.
- `projects/week-3-task-5/README.md`: запуск, API, границы исполнения, ограничения, сценарий видео на три минуты и команды тестирования. Дополнительные зависимости не добавлены; Python stdlib и существующий frontend.

Каталоги данных исключены из Git. Рабочее дерево содержит прежние изменения и другие незакоммиченные проекты; они не относятся целиком к дню 15. Commit и push не выполнялись.

## Проблемы и откаты

Дефектов приложения при финальной Validation не обнаружено; откатов реализации не было. В проверочном скрипте исправлены арифметическое ожидание финальной ревизии (правильно 13, не 15) и подтверждение существующего диалога создания чата. Уже завершённые шаги не повторялись.

После успешных assertions живого запроса диагностический вывод столкнулся с Windows `cp1252 UnicodeEncodeError`. Ошибка относится к печати результата в проверочном скрипте; HTTP-запрос и проверки завершились успешно. Второй платный запрос не выполнялся.

## Ограничения

- `kind` доказывает соответствие типизированной формы этапу, но не смысл свободного текста; то же ограничение относится к полям инвариантов.
- `passed` — явно сохранённая оценка пользователя. Приложение самостоятельно тесты не запускает.
- Owner-lock находится в памяти одного локального процесса; несколько серверных процессов потребуют общей координации. Cookie обеспечивает локальную изоляцию, полноценной системы аккаунтов нет. SQLite не шифрует переписку.
- Токены оцениваются эвристикой; таблица стоимости историческая. Один живой запрос не покрывает сетевые сбои, все этапы и все ответы провайдера.
- Ветвление создаёт новую задачу planning; историческая FSM из checkpoint не восстанавливается. Данные дня 14 автоматически не переносятся.
