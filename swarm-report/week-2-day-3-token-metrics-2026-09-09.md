# День 8 — токены, контекст и стоимость

Дата: 2026-09-09. Статус: Done.

## Задача

На основе вчерашнего `projects/week-2-task-2` создать новый день в `projects/week-2-task-3`: показать токены текущего запроса, истории и ответа; продемонстрировать короткий, длинный запрос и переполнение; объяснить рост расходов при накоплении истории и отказ при превышении окна.

## Research

- Сохранена архитектура Python stdlib + SQLite + vanilla JS и визуальная система GOOST CHAT.
- Накопленный `total_tokens` не равен размеру контекста. Локальные оценки отделены от фактического API usage и обозначены знаком ≈.
- Выбрано учебное окно приложения 2048 токенов с резервом ответа 250. Переполнение должно возвращать 422 до провайдера и изменения данных.
- Стоимость — диапазон off-peak/peak через `Decimal`, с датой и источником тарифа; неизвестный usage не заменяется нулём.
- Метрики хранятся отдельно от сообщений. Сохранены проверки владельца, Host/Origin, лимиты 4000 символов и 32 KiB; пользовательские данные исключены из Git.

## Ограничения

- DeepSeek заменён локальным детерминированным mock. Живой API, фактический биллинг и расхождение оценки с tokenizer провайдера не проверялись; API-расходов проверки не создавали.
- Оценщик `utf8_bytes_div4_v1` — эвристика; 2048 — учебный лимит приложения, не окно DeepSeek. История автоматически не обрезается и не суммаризируется.
- Стоимость расчётная, зависит от доступного usage и тарифа; при недостаточных данных неизвестна. Рост стоимости не гарантирован на каждом реальном ходе из-за cache и длины ответа.
- Сохранён режим локального однопроцессного приложения с browser-cookie; постоянная публичная эксплуатация требует отдельной авторизации и ограничения расходов.
