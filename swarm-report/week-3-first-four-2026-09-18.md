# Week 3: первые четыре задания — дни 11–14

Дата: 2026-09-18. Статус: **Done**.

## Задача

Реализовать первые четыре задания третьей недели: слои памяти, пользовательские профили, состояние задачи и инварианты. Для каждого проекта подготовить короткое саммари и инструкцию проверки для видео.

## Research

База реализации — самостоятельный GOOST-проект дня 10 (`projects/week-2-task-5`). Сохранены стратегии контекста, чат, метрики, ветвление и существующий визуальный стиль.

- Память разделена по области действия: краткосрочная и рабочая принадлежат чату, долговременная — владельцу. Сохранение явное; данные передаются модели отдельно от системных правил.
- Профили принадлежат владельцу, выбор сохраняется отдельно для каждого чата. Предпочтения включаются в каждый последующий запрос.
- Состояние задачи хранится на сервере: этап, текущий шаг, ожидаемое действие и пауза. Допустимые переходы проверяет приложение.
- Инварианты имеют узкий проверяемый контракт: язык, архитектура, целочисленный бюджет. Проверяется предложение пользователя и структурированный ответ модели; смысл произвольного текста не считается доказанным.
- Изоляция владельцев, ограничения входных данных, атомарность хода и повтор запроса учитываются на уровне сервера.

## План

1. Создать четыре самостоятельных накопительных проекта `projects/week-3-task-1` … `week-3-task-4` на базе дня 10.
2. Добавить SQLite-хранение и HTTP API без новых библиотек.
3. Встроить панели памяти, профиля, состояния и инвариантов в существующий интерфейс.
4. Дополнить проверки серверной логики и браузерных сценариев.
5. Подготовить README с запуском, видео на 2–4 минуты, критериями успеха и границами гарантий.

## Validation

Платформы: Backend и Web. Результаты получены на стадии Validation; стадия Report сверила README, файлы реализации, Git-состояние и сохранённое свидетельство проверок.

- Python: четыре отдельных запуска `python -m unittest -q`, по 35 обнаруженных тестов. **134 прошли, 6 пропущены**: недоступные на ранних днях функции, распределение 3/2/1/0.
- JavaScript: **4 набора** `node --test static/week.test.cjs` прошли; `node --check` прошёл для **8 файлов** `app.js` и `week.js`.
- Edge E2E: **17/17 шагов**, отдельные изолированные контексты, временные базы и подставной провайдер за реальным HTTP-путём приложения. Проверены память, профили, FSM, инварианты, вывод недоверенной разметки текстом, сохранение состояния и смена чата во время ответа.
- Desktop 1600×1000: начало нового ответа видно, панель настроек 335 px, горизонтального переполнения нет. Mobile 390×844: открытие Enter, закрытие Escape, возврат фокуса и отсутствие горизонтального переполнения подтверждены.
- Отдельная живая проверка: один вызов DeepSeek через `ChatAgent.ask` дня 14, модель `deepseek-v4-flash`, JSON mode. Python / monolith / бюджет 500 при пределе 1000; `last_check.status=passed`, ответ `OK`. Расход: 253 входных + 26 выходных = **279 токенов**. Использованы временные данные; ключ не выводился.
- `git diff --check` прошёл; каталоги данных всех четырёх проектов исключены из Git.

Подставной провайдер проверяет поведение приложения, но не качество ответов живой модели. Единственный живой запрос — серверная smoke-проверка; полный браузерный прогон с живым DeepSeek не выполнялся.

## Границы результата

- Это локальное приложение одного процесса. Cookie отделяет владельцев в базе, но не заменяет полноценную аутентификацию. Базы SQLite не зашифрованы; блокировки владельца действуют внутри одного процесса.
- Модель получает память, профиль и состояние, но качество текста зависит от модели. Профиль задаёт предпочтения, FSM требует действий пользователя и сам по себе не доказывает качество выполнения задачи.
- Инварианты проверяют типизированные поля, а не смысл свободного `answer`. Язык и архитектура сравниваются без учёта регистра, без распознавания синонимов.
- Оценка токенов эвристическая; таблица стоимости историческая. После ошибки провайдер уже мог тарифицировать запрос.
- Видео не записывалось: подготовлены запрошенные инструкции и критерии проверки в каждом README.
